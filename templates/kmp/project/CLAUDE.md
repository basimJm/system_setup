# Acme Shop — Rules for AI Agents

Kotlin Multiplatform app (package `com.acme.shop`) generated by KMP_TEMPLATE. These rules keep it in the same shape.

## 1. Non-Negotiable Rules
1. **Clean Architecture + MVI by delegate.** Every screen follows §3. No business logic in composables, no Android/iOS
   types in `commonMain` domain code.
2. **Never hardcode.** No literal strings, colors, `dp`/`sp`, shapes, durations, alphas, URLs, hosts, keys, IDs, limits or
   magic numbers in feature or component code. Use string resources, design tokens (`core/design-system/.../theme`),
   named constants (`*Constants.kt`) or per-environment build config (§5). `python3 scripts/ci/policy_checks.py all`
   fails on violations; `config/policy-baseline.json` and `config/detekt/baseline.xml` may only shrink.
3. **Arabic and English for every resource**: `values/strings.xml` and `values-ar/strings.xml` with the same keys.
4. **Every build variant builds**: Android `dev`/`prod` × `debug`/`release`; iOS `Debug-Dev`, `Release-Dev`,
   `Debug-Prod`, `Release-Prod` (schemes `iosApp-Dev`, `iosApp-Prod`).
5. **Run the gate** `scripts/ci/run_local_checks.sh` before every commit (`SKIP_IOS=1` skips iOS).
6. **No warnings** (`allWarningsAsErrors`, Lint `warningsAsErrors`); no `!!`, unchecked casts, empty `catch`,
   `GlobalScope`, `runBlocking`, `TODO()`, `println`. Failures are `AppResult`/`AppError`, never thrown to the UI.
7. **Files ≤ 300 lines.** **Portrait + landscape, phone to tablet, RTL + LTR, light + dark, font scale 200 %.**
8. Never commit secrets (keystores, `local.properties`, signing). Firebase files live only in
   `androidApp/src/{dev,prod}/google-services.json` and `iosApp/Firebase/{dev,prod}/GoogleService-Info.plist`.
9. A new library or version goes through `gradle/libs.versions.toml` with the reason in the commit.

## 2. Modules
`androidApp` / `iosApp` hosts · `composeApp` shell (theme, navigation host, DI aggregation, push, deep links) ·
`core/{common,domain,data,network,storage,security,realtime,navigation,mvi,analytics,firebase,notification,ui,design-system,di}` ·
`feature/<name>/{domain,data,presentation,di}` (reference: `feature/sample`) · `build-logic/convention` plugins.
Dependency direction: `presentation → domain ← data`; `di` wires them; `core/design-system` never imports a feature.

## 3. Screens (Clean Architecture + MVI by delegate)
- `domain`: models, repository interfaces, one use case per action returning `Flow<AppResult<T>>`.
- `data`: DTOs + Ktor service, repository implementation mapping DTO → model.
- `presentation`: `controller/contract/<Name>Contract.kt` (`UiState`, `UiAction`, `SideEffect`),
  `controller/vm/<Name>ViewModel.kt` extends `BaseViewModel` (state only via `updateState`, effects via
  `emitSideEffect`, reducer in `handle(event)`), `screen/<Name>Screen.kt` stateless `(state, onAction)` with previews,
  `navigation/`, `di/`.
- Analytics: `TrackScreen(<Feature>Analytics.SCREEN)` per screen; view models call `trackAction` for user intents.
- Unit tests in `commonTest` for every view model, use case and mapper (fakes, not mocks).
- New feature: copy `feature/sample`, add its modules to `settings.gradle.kts`, `ComposeAppPlugin.FEATURE_MODULES`,
  `appModules` (`composeApp/.../app/ui/App.kt`) and its graph to `MainNavigation`.

## 4. Design System
Tokens in `core/design-system/.../theme` (`AppTheme.colors|spacing|shapes|typography|sizes|elevation|alpha|motion|adaptive|glass`).
Build screens from `App*` components only (`AppScreen`, `AppCard`, `AppGlassSurface`, `AppButton`, `AppTextField`, …).
Start/End, never Left/Right.

## 5. Environments
Android `gradle.properties` (`DEV_/PROD_API_BASE_URL`, `*_WEB_BASE_URL`, `*_DATA_SOURCE` = `mock|remote`) → `BuildConfig`;
API prefix `/app/v1` (auth refresh in `core/network`), realtime namespace in `core/realtime` (`RealtimeDefaults`);
mock data = `MockFixture` bindings per feature (`feature/sample/data/.../SampleFixtures.kt`);
iOS `iosApp/Configuration/{Dev,Prod}.xcconfig` → `Info.plist`; shared code reads `AppEnvironment` (Koin), never a literal.
Per-developer iOS signing: `iosApp/Configuration/Local.xcconfig` (git-ignored).

## 6. Performance
Stable state types, keys + content types in lazy lists, `collectAsStateWithLifecycle`, fast-changing state read in
draw/layout, no main-thread blocking, images sized to their slot (Coil caches). The gate checks R8 and the APK budget.
