# ADR-0006 — Rich text: a Markdown-subset editor that emits sanitized HTML

- **Status:** accepted (template decision)
- **Context:** long texts (legal pages, help texts) are edited in Arabic and English. Appendix C suggested a headless editor such as Tiptap with a strict sanitizer. Tiptap + ProseMirror is about 70 KB gzip; the release budget is 200 KB total and the current production bundle leaves about 27 KB. The browser's `document.execCommand` (the usual way to build a small WYSIWYG) is deprecated, and rules forbid deprecated APIs.
- **Decision:** `RichTextEditor` edits a small Markdown subset (headings `##`/`###`, bold, italic, bullet and numbered lists, links, paragraphs) in a `textarea` with a toolbar that wraps the selection, a live preview, and the right reading direction per language. The output is HTML produced from that grammar and passed through an allow-list sanitizer (`p h2 h3 ul ol li strong em a br`; links only `https`, `http`, `mailto`; `rel=noopener noreferrer`). Existing HTML from the server is sanitized and converted back to the subset when loaded. The server sanitizes again (never trust the client).
- **Consequences:** about 4 KB instead of 70 KB; no new dependency; output cannot contain scripts, styles, iframes or event handlers by construction. Editing is Markdown-style, not click-to-format WYSIWYG, and HTML outside the allow-list is flattened when a page is loaded. If the owner requires WYSIWYG, revisit this ADR with a budget change for a lazy editor chunk.
