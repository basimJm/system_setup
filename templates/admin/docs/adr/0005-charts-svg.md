# ADR-0005 — Charts: hand-written SVG components, no chart library

- **Status:** accepted (template)
- **Context:** the admin needs line, bar, stacked bar, donut, funnel, cohort heatmap and sparkline charts (Admin PRD §2: every chart has tooltips, "View data" and export), in Arabic and English, light and dark, on phones to desktops, inside a gzip budget (`scripts/budget.json`: 40 KB entry, 80 KB per chunk). Chart libraries (Recharts, Chart.js, ECharts) add 40-300 KB, draw to canvas or ship their own theming, and need work to follow RTL and our tokens.
- **Decision:** small SVG components with pure, unit-tested geometry (`presentation/utils/chartMath.ts`), colours only from tokens (`--chart-1..6`, tone colours for the heatmap), a responsive `viewBox`, native `<title>` tooltips and an accessible summary. Every chart is wrapped in `ChartFrame`, which adds the "View data" table and a client-side CSV export (cells that start with `= + - @` are neutralised against spreadsheet formula injection). Time axes stay left-to-right in Arabic (numbers and dates are read that way); legends, tables and text follow the page direction. Sparklines are inline in KPI cards and are exempt from "View data" (their value is in the card).
- **Consequences:** about 10 KB of source instead of a library; we own the accessibility and RTL behaviour. A chart type that is not in the list (map, radar, candlestick) means revisiting this ADR before adding a library.
