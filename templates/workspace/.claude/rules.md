# __SYSTEM_NAME__ — Mandatory Rules (all projects, every task)

> Read on demand; the hard rules are in `CLAUDE.md`, and `.claude/settings.json` hooks enforce them. Project folders may add stricter rules; they never relax these. Created __DATE__ from the workspace template (one verification loop, per-project session/memory, backlog tool, batched verification, parallel-agent rules).

## 1. Token Efficiency (read once, work from the task row)
- **The picture comes from the map.** Session start prints `scripts/map.py`; `CLAUDE.md`, `.claude/memory.md` and the project's `CLAUDE.md` + `.claude/{session,memory}.md` are already loaded. Details: `python3 scripts/recall.py <words>`, then read only those lines. `tasks.py check` fails when a loaded file grows past its budget (`.claude/projects.json`).
- **Sessions stay short:** every request resends the whole context, so long sessions are the biggest cost. One task per session, `/clear` after a merge.
- **Backlogs are read only through the tool.** `python3 scripts/tasks.py next <project>` gives the one task to do (ID, title, branch, needs, notes, session file); `show <ID>`, `blocked`, `board`, `check`. Never open a `*_Tasks.md` file whole; never list all tasks.
- **Requirements by section.** A task row names its PRD screens/sections and OpenAPI operations; read only those headings (`grep -n "^### S07"` then `sed -n`), never a PRD/BRD/design script whole. Design files are visual reference only, opened for UI tasks.
- **One project per session.** Work inside one project folder so only its `CLAUDE.md`/session/memory load. Cross-project facts live in `INTEGRATION.md` (read §1–§5 once when a task touches two projects) and in root `memory.md`.
- Start by inspecting `git status`, the relevant files and the existing implementation; search for symbols before opening files; read only needed ranges; never re-read files you just wrote.
- Avoid dumping build logs, dependency trees or generated files into context. Prefer `python3 scripts/qa.py <project>` and read only its summary.
- Each project's `.claude/session.md` holds only the task in progress; merged blocks go to `docs/knowledge/session-archive.md`. `.claude/memory.md` holds only what every session needs; other facts go to `docs/knowledge/facts.md`.

## 2. Understand Requirements Before Coding
- Identify the exact requested outcome; inspect the implementation, callers, dependencies and existing tests.
- Convert the request into explicit acceptance criteria in the **project's** `.claude/session.md` task block, naming the PRD/BRD/BUSINESS_DOMAIN sections and OpenAPI operations touched.
- Identify constraints, edge cases, regressions. Distinguish requirements from assumptions. Ask a concise question only when a missing detail materially affects correctness and the repo cannot answer it.
- Do not expand scope, refactor unrelated code or add features without justification.
- Source of truth: PRD > BRD > Design Script > design files (`CLAUDE.md` §2). Wire format: the server OpenAPI snapshot (`INTEGRATION.md` §2). A client never builds a screen on an endpoint the contract does not have: it files a server task and marks its row BLOCKED on it.

## 3. Delivery Rules
1. **Unit tests for every task.** Every code change ships with unit tests covering the acceptance criteria, edge cases and the regression it fixes. All must pass. No tests → task not done.
2. **Branch per task from the project's master, checked before the first edit.** Masters: __MASTERS_LIST__ (`INTEGRATION.md` §1). `git fetch origin && git branch --no-track feat/<prefix>-NNN-<key> origin/<master> && git checkout feat/...`; `git branch --show-current` must show the task branch before editing. PRs target the master, never `main`. The owner merges masters into `main`; if a master is behind `main`, merge `main` into it by PR first. Its three clauses are rules of their own:
   - **Never commit or push to `main` or a master.** The task branch is the only place work happens.
   - **Never force-push.**
   - **Never skip git hooks** (`--no-verify`) and never disable them (line workers: rule 15).
3. **No hardcoded values anywhere.** No URLs, hosts, ports, keys, secrets, IDs, user-visible strings, colors, sizes, limits, timeouts or magic numbers in code. Use config/env, constants, localization resources, design tokens or server-driven settings.
4. **One verification loop before push** (`Loops: 1/1`): re-check every acceptance criterion once, covering requirements coverage, edge cases/errors/security/no-hardcode, and tests/build/lint green + PRD/BRD consistency. Record it in the project's `session.md`.
5. **Four-role review before push** (`.claude/hooks.md` §2). Record `Review: PASSED`. Fix every blocking finding first.
6. **Status through the tool, both sides at once.** When a task starts: `python3 scripts/tasks.py set <ID> "IN PROGRESS"`; PR open: `IN REVIEW`; merged: `DONE`. The tool unblocks dependents in other projects and rebuilds the board in `INTEGRATION.md`; commit those file changes with the task. A contract change names the affected client tasks in the task block.
7. **Keep the project's `session.md` and `memory.md` current** (`.claude/hooks.md` §3); root `session.md` index line updated when a project's current task changes; root `memory.md` only for cross-project facts.
8. Never commit secrets; never edit `.env*` files without explicit permission. Config values the owner must set are requested by **key name only**, never typed into chat by the agent, never echoed back.
9. **Gates are local unless a project enables CI:** before every push run the project's gate (its `CLAUDE.md` names the command) green, plus the browser/simulator check of rule 11 for UI projects; e2e only when the owner asks.
10. **Autonomous backlog flow (once the owner grants it).** After the gate is green: push, open the PR into the master, merge it (merge commit), return to the updated master and start the next backlog task, until the backlog has no ready task. Stop only on `PENDING`/`BLOCKED` tasks and report them. If the owner says stop, stop.
11. **Run every UI project in a browser/simulator before committing**: use the changed screens in every language, light and dark, phone and desktop/tablet; console clean; measure widths/positions instead of inferring them. State what was opened in the commit/PR body.
12. **Pushes and merges through the Terminal panel bypass the Bash guard hook**: the `Loops: 1/1` and `Review: PASSED` lines must be written (and true) in the project's `session.md` before any push or merge made that way. The guard reads `session.md` **before** the command runs: write the block in one call, push in the next.
13. **Batched verification (owner decision; overrides the timing of §3.4/§3.5/§3.9/§3.11).** Per task: implement, write the unit tests, run the in-sandbox policy checks, record the task block (`Loops: 0/1`, `Review: PENDING`), commit on the task branch and branch the next task from it. **After every five tasks: run the unit tests only** (one host-test run), fix failures, record `Loops: 1/1` + `Review: PASSED` for the five blocks (review = the code reading of the batch; UI check deferred), open one PR from the last branch into the master, merge, set the five tasks DONE. **After the whole backlog:** linters, the full gate (every build variant/configuration), and one end-to-end journey on emulator and simulator, fixing what they find in a final batch.
14. **Report deviations honestly.** When a rule was not fully applied, say so in the task block and in the final answer. Never record `Loops: 1/1` or `Review: PASSED` for a pass that did not happen; a block stays `0/1`/`PENDING` until the tests and review actually ran.
15. **Feature line.** A feature across modules goes through `scripts/line.py`: a two-page `features/<name>/PACKET.md`, the contract first, then a thin worker per module, `scripts/qa.py`, one reviewer, fix workers, and `line.py merge`. One task in one module stays a normal session. **Hooks in a worker:** `guard_git` and `check_hardcoded` stay on, passed through `--settings`; `SessionStart` and `UserPromptSubmit` only add context and do not load; `Stop` does not load because `line.py` does its job: QA checks the tests changed, and `Loops`/`Review` are written only after QA and the reviewer passed on the final code. The review is one reviewer through the four roles, not four sessions. Workers are refused `git commit`, `push`, `merge` and `gh`; the script commits, and pushes only through the same `guard_git` check. A worker hitting an open business rule stops with `BLOCKED: <question>`, which goes on the owner's page. The line opens no browser, emulator or simulator and runs no iOS build; every report says so.

## 4. Parallel Agents and the Environment (learned the hard way)
1. **One agent per master, one worktree per agent** (`.claude/worktrees/<agent>` is ignored by git). Agents touching the same backlog file or board must merge the master into their worktree before committing status rows; the hooks resolve the checkout from the command's `cwd`, so each worktree is judged on its own branch.
2. **One heavy gate at a time per machine.** Gradle, Xcode and `npm` builds from several agents collide on the shared daemon/cache (`Timeout waiting to lock …`, out-of-memory, 95 % disk). Run the builds serially; two parallel agents is the practical maximum when both build; six was the recorded mistake.
3. **Never `--stop` or kill shared daemons** (Gradle, emulators, a local server another agent is testing against). Finish or hand over instead.
4. **Commit small and often.** Long-running agents are dropped by connection errors (`ECONNRESET`, usage limits) and by 10-minute stalls on long builds; uncommitted work in a dropped worktree is the most expensive loss. Commit before every long build.
5. **Poll long builds with short reads.** Start a long command in the background or a terminal tab and read its tail at intervals; never block one turn on a 30-minute build.
6. **Terminal panel discipline.** Tabs are limited (about six per session) and echo their whole screen when read or closed: open one per long process, close it after use, keep its output short (`tail`, `grep`).
7. **The sandbox cannot** write `.claude/hooks/`, `.claude/settings*.json`, `.git/config` (no `-u` upstream, use `git branch --no-track <name> origin/<master>`), bind local ports, or run `gh`; those steps go through the Terminal panel (outside the sandbox) and must respect rule 12. Ask the owner for `sandbox.network.allowLocalBinding: true` when a local stack must run from Bash.
8. **A dropped agent is resumed in its own worktree on its own branch**; if it cannot be resumed, a fresh agent continues there (commits and uncommitted files are intact). Leave your own shell in the main checkout on a master, not inside another agent's worktree, or the Stop hook judges the wrong branch.
9. **Clean up finished worktrees** (`git worktree remove`) after their PR merged: each one holds a full build cache (GB) and the disk filling up fails the next gate.
10. **Brief subagents tightly:** goal, files to read, what is ruled out, narrow scope, expected report length. Long reports and duplicated hypotheses cost more than the work they save.
