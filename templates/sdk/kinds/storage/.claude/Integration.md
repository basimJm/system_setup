## 1. Purpose and boundaries
Presigned uploads (server-generated keys, content type + size + TTL constraints), upload confirmation (existence, stored type vs claimed type, size; rejected objects deleted), public CDN URLs, short-lived signed URLs for private objects, server-side read/write, batched delete.

**Not in this package:** who may upload what (consumer), image variants / transcoding / antivirus (consumer or a later adapter), serving files (CDN).

## 2. Architecture
```
consumer ──> createStorage(options) ──> StorageProvider (port, src/types.ts)
                                        ├── adapters/fake      (memory + call log + failure injection; tests)
                                        ├── adapters/memory    (dev on localhost, no credentials)
                                        └── adapters/s3        (S3-compatible: AWS, MinIO, Spaces, R2; SigV4 in node:crypto)
kernel (src/kernel.ts): errors · zod options + prod rules · redacting logger · retry/backoff · timeout
```
- `provider` chooses the adapter; `environment: 'prod'` refuses `fake` and `memory` (`DEV_ONLY_PROVIDERS`).
- Adapters never leak vendor types; every HTTP status is mapped (§5).
- `fetch` is injectable (tests, proxies); defaults to the global one.

## 3. Public API (port)
```ts
interface StorageProvider {
  createUploadUrl(r: { key; visibility: 'PUBLIC'|'PRIVATE'; contentType; maxBytes; expiresInSec }): Promise<{ url; method: 'PUT'; headers; expiresAt }>;
  confirmUpload(r: { key; visibility; contentType; maxBytes }): Promise<
    | { status: 'CONFIRMED'; size; contentType }
    | { status: 'REJECTED'; reason: 'NOT_FOUND'|'EMPTY'|'TYPE_MISMATCH'|'TOO_LARGE' }>;  // rejected = deleted
  getPublicUrl(key): string;                       // pure, CDN base + key
  getSignedUrl(r: { key; expiresInSec }): Promise<string>;
  read(key): Promise<Buffer | null>;
  write(r: { key; body; contentType; visibility }): Promise<void>;
  delete(keys: readonly string[]): Promise<void>;  // missing keys ignored, batched
}
createStorage(options: StorageOptions): StorageProvider
```
Also exported: `resolveConfig`, `FakeStorage` (`calls`, `failWith`, `simulateUpload`, `has`, `size`), `MemoryStorage`, `S3Storage`, `mapStatus`, `presignUrl`/`signHeaders` (SigV4), constants (`ERROR_CODES`, `PROVIDERS`, `VISIBILITIES`, `REJECTION_REASONS`) and the kernel.

## 5. Status and result mapping
| Store answer | Normalized |
|---|---|
| 200 / 204 | success |
| 404 | `read` → `null`; `confirmUpload` → `REJECTED: NOT_FOUND`; `delete` → success |
| HEAD size 0 / > maxBytes / type ≠ claimed | `REJECTED: EMPTY` / `TOO_LARGE` / `TYPE_MISMATCH` (object deleted) |
| HEAD without `content-length` | `MALFORMED_RESPONSE` |
| 403 | `AUTH_FAILED` |
| 429 / 503 | `RATE_LIMITED` (retry) |
| other 5xx | `UNAVAILABLE` (retry) |
| 400 | `VENDOR_ERROR` |
| anything else | `UNKNOWN` (never success) |
| fetch rejection / timeout | `NETWORK_ERROR` / `TIMEOUT` (retry) |

## 6. Error model
`SdkError { code, message, retryable, cause, details }` (no secrets). Codes: kernel (`__SDK_PREFIX___CONFIG_INVALID`, `VALIDATION_FAILED`, `AUTH_FAILED`, `NETWORK_ERROR`, `TIMEOUT`, `RATE_LIMITED`, `UNAVAILABLE`, `VENDOR_ERROR`, `MALFORMED_RESPONSE`, `UNKNOWN`) + `KEY_INVALID`, `ACCESS_DENIED` (reserved), `TOO_LARGE`.

## 7. Environments
Dev: `memory` or `fake` without credentials, or `s3` against MinIO (`endpoint` http, path style). Prod: `s3`, https CDN + endpoint, credentials present, distinct buckets.

## 8. Performance notes
Presigning is pure (no network). Reads are bounded by `readMaxBytes`. Deletes run `DELETE_CONCURRENCY` (20) requests at a time across both buckets. Retry only on retryable errors with capped backoff + jitter.

## 9. Testing
`npm test` (coverage gate: 100 % functions, ≥ 95 % lines/branches; `index.ts`/`kernel.ts` are re-exports and excluded), `tests/helpers/miniS3.ts` = S3 wire emulator behind `FetchLike` (no sockets), `tests/sigv4.test.ts` reproduces the AWS documentation signatures, `npm run test:loop` = 100 lifecycles × memory + S3 adapter, 20 concurrent, nothing left behind, `npm run test:smoke-package` = packed tarball used through CJS and ESM.

## 10. Adoption guide (any project)
1. `npm i __NPM_SCOPE__/storage`; map env → `StorageOptions` in the consumer's config layer (no literals in code).
2. `const storage = createStorage(options)` once; inject it where files are handled.
3. Upload flow: server builds the key → `createUploadUrl` → client PUTs with the returned headers → server `confirmUpload` → store `size`/`contentType`; a `REJECTED` result is final (object already deleted).
4. Tests: `provider: 'fake'` + `simulateUpload`; `failWith` for failure paths.

## 11. Open questions / assumed-missing requirements
- Real AWS/MinIO/CDN calls not executed by the generator; MinIO run in the consumer's dev stack.
- Content sniffing (magic bytes) is not done: the stored `Content-Type` is compared to the claimed one. Add a sniffing step in the consumer or a later adapter if needed.
- Signed URLs are S3 presigned GETs; a CDN-signed URL adapter is a later task.
