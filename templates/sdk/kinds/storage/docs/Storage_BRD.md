# __SYSTEM_NAME__ — Business Requirements Document (BRD)
## Package: `__NPM_SCOPE__/storage` (`__SDK_DIR_storage__`)

| Field | Value |
|---|---|
| Owner | __SYSTEM_NAME__ backend team |
| Consumer | `__SERVER_DIR__` |

## 1. Executive Summary
One provider-independent file-storage package used by every __SYSTEM_NAME__ service: clients upload directly to object storage through short-lived presigned URLs, the backend confirms what arrived, public files are served from a CDN and private files through short-lived signed URLs.

## 2. Business Context
Uploads (photos, documents, exports) must never pass through the API servers, must be constrained (type, size, expiry) and must be verifiable after the fact. The vendor (AWS S3, MinIO, Spaces, R2) must be replaceable by configuration.

## 3. Goals
- G1 Direct-to-storage uploads with server-generated keys and server-set limits.
- G2 Every upload confirmed before it is referenced by business data; wrong uploads removed.
- G3 Public vs private visibility with the right URL kind for each.
- G4 Works on a developer laptop without credentials; strict in production.

## 4. Scope
### 4.1 In Scope
Presigned PUT, confirmation (exists / empty / size / type), public CDN URL, signed private GET URL, server read/write, batched delete, fake + memory adapters, S3-compatible adapter.
### 4.2 Out of Scope
Ownership and permission decisions, image processing, virus scanning, multipart uploads (future task), CDN invalidation.

## 5. Business Requirements
| ID | Requirement | Acceptance |
|---|---|---|
| STO-R1 | A client never chooses an object key | key supplied by the backend; shape validated (`KEY_INVALID`) |
| STO-R2 | An upload URL expires and is bound to a content type | `expiresInSec` ≤ configured maximum; headers returned to the client |
| STO-R3 | A confirmed upload has the claimed type, is not empty and is within `maxBytes` | `CONFIRMED { size, contentType }` else `REJECTED { reason }` and the object is deleted |
| STO-R4 | Public objects have a stable CDN URL; private objects only short-lived URLs | `getPublicUrl` pure; `getSignedUrl` TTL ≤ configured maximum |
| STO-R5 | Deleting a missing object is not an error | `delete` idempotent |
| STO-R6 | Production refuses fake adapters, plain-http endpoints and missing credentials | `CONFIG_INVALID` naming the field |

## 6. Non-Functional Requirements
Typed errors with stable codes; retries only on transient failures; no secrets logged; bounded memory (`readMaxBytes`); ≥ 95 % test coverage; ESM + CJS.

## 7. Success Metrics
Zero uploads referenced without confirmation; vendor switch = configuration change only; `npm run verify` green on every change.

## 8. Risks & Mitigations
| Risk | Mitigation |
|---|---|
| Clients lie about the content type | stored type compared on confirm; consumer may add magic-byte sniffing |
| Leaked presigned URLs | short TTLs, PUT bound to one key, private reads signed per request |
| Vendor outage | retry with backoff; typed `UNAVAILABLE`/`RATE_LIMITED` for the consumer's fallback |

## 9. Open Items
Multipart uploads for large files; CDN-signed URLs; content sniffing location (see `.claude/Integration.md` §11).
