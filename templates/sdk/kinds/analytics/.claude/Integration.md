## 1. Purpose and boundaries
Server-side event tracking behind one port: `track`, `linkIdentity`, `flush`, with queueing, batching, retries and loss accounting. Best effort by design: analytics never blocks or breaks the caller.

**Not in this package:** event taxonomy and dashboards (consumer / warehouse), client-side tracking (apps), PII policy (consumer decides what goes into properties; the logger redacts secret-looking keys).

## 2. Architecture
```
consumer ──> createAnalytics(options) ──> AnalyticsTracker (port) = Tracker (queue → batches → sink, retry, timer)
                                           └── AnalyticsSink port: MemorySink | FakeSink (dev/tests) | HttpSink (generic collector) | custom
kernel: errors · zod options + prod rules · redacting logger · retry/backoff · timeout
```

## 3. Public API (port)
```ts
interface AnalyticsTracker {
  track({ name; userId?; anonymousId?; properties?; occurredAt? }): void;   // throws VALIDATION_FAILED only
  linkIdentity({ anonymousId; userId; occurredAt? }): void;
  flush(): Promise<void>;
  readonly pending: number;
  readonly dropped: number;
  close(): Promise<void>;
}
interface AnalyticsSink { name; isFake?; deliver(batch: Envelope[]): Promise<void>; close?() }
createAnalytics(options): Analytics   // Tracker + { sink }
```
`Envelope = { id; type: 'track' | 'identity'; name; userId?; anonymousId?; properties; occurredAt }`. The http sink posts `{ events: Envelope[] }`.

## 5. Status and result mapping
| Situation | Result |
|---|---|
| collector 2xx | batch delivered |
| 401 / 403 | `AUTH_FAILED` (not retried) → batch dropped + `dropped` += size, error log |
| 429 / 5xx / network / timeout | retried with backoff; after `retry.maxAttempts` dropped and counted |
| other 4xx | `VENDOR_ERROR`, dropped |
| queue at `maxQueue` | oldest event dropped, warning |
| `track` after `close` | `UNAVAILABLE` thrown |

## 6. Error model
`SdkError { code, message, retryable, cause, details }`. Codes: kernel + `__SDK_PREFIX___SINK_FAILED` (non-SDK sink throws), `__SDK_PREFIX___QUEUE_FULL` (reserved for a strict mode).

## 7. Environments
Dev: `memory` / `fake` (events on `analytics.sink.events`). Prod: `http` to the warehouse collector or a custom vendor sink.

## 8. Performance notes
`track` is O(1) and synchronous; one timer at a time; batches bounded; deliveries serialised per tracker so the sink sees order; retries only on retryable errors.

## 9. Testing
`npm test` (coverage gate; `tests/helpers/timers.ts` drives the flush timer), `npm run test:loop` = 5 000 events from 20 producers through a flaky sink, exactly-once or counted; `npm run test:smoke-package` through CJS and ESM.

## 10. Adoption guide (any project)
1. `createAnalytics(...)` once per process; `await analytics.close()` on shutdown (flushes).
2. Call `track` from services/jobs with a stable event vocabulary; `linkIdentity` after login/registration.
3. Watch `dropped` (expose as a metric); never put secrets in properties.
