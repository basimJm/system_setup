## 1. Purpose and boundaries
Generate one-time codes, deliver them through a pluggable channel, verify them with limits and blocks, and hand the consumer a **single-use `otpToken`** that its own endpoints spend. The package decides nothing about users or sessions.

**Not in this package:** the delivery vendor (a channel adapter per vendor, added as a task), JWT/session issuance, user lookup, UI copy.

## 2. Architecture
```
consumer ──> createOtp(options) ──> OtpProvider (port, src/types.ts) = OtpService
                                    ├── CodeStore   port: memory (dev, `scope: local`) | consumer's Redis (`scope: shared`)
                                    └── OtpChannel  port: FakeOtpChannel (dev/tests) | vendor adapter (WhatsApp, SMS, email)
kernel (src/kernel.ts): errors · zod options + prod rules · redacting logger · retry/backoff · timeout
```
Store keys: `code:<purpose>:<phone>` (HMAC hash + expiry), `req:<phone>` (window counter), `wrong:<phone>`, `block:<phone>`, `cooldown:<purpose>:<phone>`, `token:<otpToken>`. A shared store must implement each call atomically (Redis `SET PX`, `SET NX PX`, `INCR` + `PEXPIRE` on first, `PTTL`, `DEL`).

## 3. Public API (port)
```ts
interface OtpProvider {
  request({ phone, purpose, language }): Promise<
    | { outcome: 'SENT'; otpLength; resendAfterSeconds; expiresInSeconds; deliveryId }
    | { outcome: 'RATE_LIMITED' | 'BLOCKED'; retryAfterSeconds }>;
  verify({ phone, purpose, code }): Promise<
    | { outcome: 'VERIFIED'; otpToken; expiresInSeconds }
    | { outcome: 'WRONG_CODE'; attemptsRemaining }
    | { outcome: 'EXPIRED' }
    | { outcome: 'BLOCKED'; retryAfterSeconds }>;
  consumeToken({ otpToken, phone, purpose }): Promise<{ valid: true } | { valid: false; reason: 'UNKNOWN_TOKEN' | 'MISMATCH' }>;
  resetLimits(phone): Promise<void>;      // admin unblock
  getConfig(): { otpLength; resendAfterSeconds };
  close(): Promise<void>;
}
createOtp(options: OtpOptions): Otp   // Otp = OtpService + { store, channel }
```
Ports to implement for a vendor: `OtpChannel { name; isFake?; send(message): Promise<{ id }> }`, `CodeStore { scope; set; get; delete; setIfAbsent; increment; ttlMs; close? }`.

## 5. Status and result mapping
| Situation | Result |
|---|---|
| phone blocked | `BLOCKED { retryAfterSeconds }` (request and verify) |
| cooldown active | `RATE_LIMITED { retryAfterSeconds }` |
| requests in window > limit | block started → `BLOCKED` |
| channel throws | code + cooldown removed, `DELIVERY_FAILED` (retryable; an `SdkError` from the channel is kept) |
| no code / expired / already used | `EXPIRED` |
| wrong code | `WRONG_CODE { attemptsRemaining }`; at the limit → block + pending code deleted |
| right code | code deleted atomically (one winner), limits reset, `VERIFIED { otpToken }` |
| token unknown / expired / replayed | `UNKNOWN_TOKEN`; wrong phone or purpose → `MISMATCH` (token burned) |
| store throws | `STORE_FAILED` (retryable) |

## 6. Error model
`SdkError { code, message, retryable, cause, details }`. Codes: kernel + `__SDK_PREFIX___DELIVERY_FAILED`, `__SDK_PREFIX___STORE_FAILED`. Validation (`VALIDATION_FAILED`): phone E.164, purpose `UPPER_SNAKE`, language BCP 47, code digits of `codeLength`, token hex.

## 7. Environments
Dev: `provider: 'fake'`; the code is `otp.channel.lastCode(phone)` or `fixedCode`. Prod: `provider: 'code'` with a shared store, a real channel and a strong secret.

## 8. Performance notes
Every call is a handful of O(1) store operations; no network besides the channel. Hashes are HMAC-SHA256 with constant-time comparison; tokens are 32 random bytes.

## 9. Testing
`npm test` (coverage gate), `tests/helpers/sharedStore.ts` for production rules, `npm run test:loop` = 200 flows × 25 concurrent with wrong codes, delivery failures and double consumes, store empty afterwards; `npm run test:smoke-package` through CJS and ESM.

## 10. Adoption guide (any project)
1. Implement `CodeStore` on the project's Redis (or reuse a published adapter) and one `OtpChannel` per vendor.
2. `createOtp({ environment, provider: 'code', store, channel, secret, ... })` once.
3. Endpoints: `POST …/otp/request` → `request()`; `POST …/otp/verify` → `verify()` and return `otpToken`; login/register/sensitive endpoints take `otpToken` and call `consumeToken()` before acting.
4. Tests: `provider: 'fake'` + `channel.lastCode(phone)`.

## 11. Open questions / assumed-missing requirements
- No vendor channel yet (`OTP-002`); templates per language belong to the channel adapter.
- Per-IP / per-device limits are not implemented (consumer middleware or a later option).
- Delivery status webhooks (sent/delivered/failed) are a channel concern (`OTP-004`).
