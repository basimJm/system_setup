## 1. Purpose and boundaries
Hosted-checkout payments behind one port: create a checkout session, verify its state server-side, refund (full or partial, idempotent), parse and authenticate webhooks. Money is **integer minor units** with an ISO 4217 code; the package has no notion of orders, deposits or policies (consumer).

**Not in this package:** card data (never touches the backend), pricing / deposit rules, payouts, reconciliation reports, vendor SDKs (adapters).

## 2. Architecture
```
consumer ──> createPayments(options) ──> PaymentGateway (port, src/types.ts)
                                         ├── adapters/fake   FakeGateway: in-process ledger, settle() returns the signed webhook
                                         └── adapters/http   HttpGateway: generic JSON protocol over fetch (Bearer, Idempotency-Key)
mock/   Ledger (sessions, refunds, idempotency, webhooks) · MockGateway.handle() (protocol, transport-free) · startMockGateway() (node:http, localhost)
kernel: errors · zod options + prod rules · redacting logger · retry/backoff · timeout
```
The mock gateway speaks the same protocol the `http` adapter consumes, so a dev stack runs end to end on localhost without a vendor. A vendor adapter later either speaks this protocol (translation service) or implements the port directly.

## 3. Public API (port)
```ts
interface PaymentGateway {
  createSession(r: { orderId; amount; currency; customer; description?; returnUrl; cancelUrl?; metadata?; destinations?; idempotencyKey }):
    Promise<{ sessionId; redirectUrl; expiresAt; status }>;
  verify(sessionId): Promise<{ sessionId; status: 'PENDING'|'PAID'|'FAILED'|'EXPIRED'|'REFUNDED'|'UNKNOWN'; amount; currency; paidAt?; reference? }>;
  refund(r: { sessionId; amount?; reason; idempotencyKey }): Promise<{ refundId; status: 'REFUNDED'|'PENDING'|'FAILED'|'UNKNOWN'; amount }>;
  parseWebhook({ headers, rawBody }): Promise<{ eventId; type; sessionId; occurredAt; data }>;
  close(): Promise<void>;
}
createPayments(options): PaymentGateway
```
`destinations` (Phase 2 split payments / sub-merchants) is validated (sum ≤ amount) and passed through; no adapter acts on it yet.

### Wire protocol (`http` adapter ⇄ mock gateway)
`Authorization: Bearer <apiKey>`, `Idempotency-Key` on POSTs, JSON bodies. `POST /v1/sessions` → 201 (200 on replay, 409 `IDEMPOTENCY_CONFLICT` when the body differs) · `GET /v1/sessions/:id` · `POST /v1/refunds` (409 `REFUND_NOT_ALLOWED`) · mock only: `POST /v1/sessions/:id/settle { status: PAID|FAILED|EXPIRED }` → `{ webhook: { headers, body } }`. Errors: `{ error: { code } }`. Webhook signature: `x-signature: t=<unix>,v1=<hmac-sha256(secret, "<t>.<rawBody>")>`, tolerance `webhookToleranceSec`.

## 5. Status and result mapping
| Gateway answer | Normalized |
|---|---|
| 200 / 201 | success; `status` outside the enum → `UNKNOWN` + warning (never success by accident) |
| wire `NOT_FOUND` / 404 | `SESSION_NOT_FOUND` |
| wire `IDEMPOTENCY_CONFLICT` | `IDEMPOTENCY_CONFLICT` |
| wire `REFUND_NOT_ALLOWED` | `REFUND_NOT_ALLOWED` |
| 401 / 403 | `AUTH_FAILED` |
| 429 | `RATE_LIMITED` (retry) |
| 5xx | `UNAVAILABLE` (retry) |
| 400 / 409 / 422 | `VENDOR_ERROR` |
| non-JSON / missing fields | `MALFORMED_RESPONSE` |
| fetch rejection / timeout | `NETWORK_ERROR` / `TIMEOUT` (retry) |
| webhook: missing/malformed header, stale, incomplete body | `WEBHOOK_INVALID`; wrong signature → `AUTH_FAILED` |

## 6. Error model
`SdkError { code, message, retryable, cause, details }`. Codes: kernel + `__SDK_PREFIX___SESSION_NOT_FOUND`, `IDEMPOTENCY_CONFLICT`, `REFUND_NOT_ALLOWED`, `WEBHOOK_INVALID`.

## 7. Environments
Dev: `fake` in tests; `http` against `startMockGateway()` for a running stack (settle through the control endpoint or `autoSettle`). Prod: real adapter, https, strong secret.

## 8. Performance notes
Idempotent POSTs (safe retries), one timeout per call, retry only on retryable errors, O(1) ledger operations in the mock.

## 9. Testing
`npm test` (coverage gate), `tests/helpers/fixtures.ts#fetchVia` routes `fetch` into `MockGateway.handle` (no sockets), `tests/server.test.ts` binds a real port, `npm run test:loop` = 150 lifecycles × 25 concurrent on the fake gateway and through the http adapter with 10 % injected outages, `npm run test:smoke-package` through CJS and ESM.

## 10. Adoption guide (any project)
1. Consumer computes the amount (deposit / full) and calls `createSession` with `idempotencyKey = <order>:<attempt>`; redirects the client to `redirectUrl`.
2. On return **and** on webhook: `verify(sessionId)`; fulfil only on `PAID`. Webhook endpoint: pass raw body + headers to `parseWebhook`, de-duplicate by `eventId`.
3. Refund policy decided by the consumer; `refund` is idempotent per key; a failed payment never creates business state.
4. Phase 2: fill `destinations` once the vendor adapter supports splits.

## 11. Open questions / assumed-missing requirements
- Gateway vendor not chosen (owner): first real adapter = `PAY-002`.
- 3-D Secure / wallet specifics belong to the vendor adapter.
- Partial refunds allowed by the port; the consumer may forbid them by policy.
