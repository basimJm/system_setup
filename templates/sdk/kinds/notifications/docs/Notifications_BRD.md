## 1. Executive Summary
One package through which every __SYSTEM_NAME__ service sends push notifications and emails: validated, de-duplicated, retried when transient, reported per device token, vendor replaceable by configuration.

## 2. Business Context
Notifications drive the core flows (requests, approvals, reminders, alerts). Jobs retry, so a message must not be sent twice; devices churn, so dead tokens must be reported back; vendors change.

## 3. Goals
- G1 One facade for push and email.
- G2 Exactly-once per business event (idempotency key).
- G3 Dead-token feedback to keep the device table clean.
- G4 Dev without vendors; strict production.

## 4. Scope
### 4.1 In Scope
Push (tokens, title/body/data, priority, collapse key), email (to, subject, text/html, reply-to, tags), idempotency, chunking, retries, per-token report, fake senders.
### 4.2 Out of Scope
Templates and translations, audience selection, scheduling, in-app inbox, vendor SDKs (adapters).

## 5. Business Requirements
| ID | Requirement | Acceptance |
|---|---|---|
| NOT-R1 | The same event never produces two sends | `idempotencyKey` → second call `duplicate: true` |
| NOT-R2 | Unregistered tokens are reported for deletion | `invalidTokens` |
| NOT-R3 | Transient vendor failures are retried, permanent ones are not | `RETRYABLE` re-sent; `FAILED` final; typed errors |
| NOT-R4 | A push can be data-only (silent) or visible | title/body optional, data bounded |
| NOT-R5 | Emails are validated before reaching the vendor | addresses, subject, text |
| NOT-R6 | Production refuses fake senders and local idempotency | `CONFIG_INVALID` naming the field |

## 6. Non-Functional Requirements
Bounded batches (≤ 500 tokens per call), bounded data payload, timeouts, no secrets in logs, ≥ 95 % coverage, ESM + CJS.

## 7. Success Metrics
Zero duplicate sends from job retries; dead tokens removed within one send; vendor change without consumer code changes.

## 8. Risks & Mitigations
| Risk | Mitigation |
|---|---|
| Vendor quota / outage | retry with backoff; typed failures for the job to reschedule |
| Idempotency store outage | typed error, the job retries later (never sends blind) |
| Oversized payloads rejected by vendors | validation up front |
