# LESSONS — what twelve agent sessions on a multi-project monorepo taught (generalized)

> Distilled from the session transcripts and the per-project memory files of a production marketplace built end to end by AI agents: a Node/Express/Mongoose/Redis/Socket.IO/BullMQ backend, a React 19 + Vite admin panel, two Kotlin Multiplatform apps (Android + iOS), five TypeScript SDK packages (ports + adapters), with a backlog tool, hooks and a four-role review. Each lesson is one or two lines with the **why**. No facts of the source system (names, hosts, ids) are kept; they would be wrong for the next one.
>
> **How a project uses it.** `SYSTEM_SETUP new` copies only the lessons that match the project's modules to `docs/knowledge/LESSONS.md` (so `scripts/recall.py` finds them) and points to them from `CLAUDE.md`. `PLAYBOOKS.md` turns the recurring ones into step lists.
>
> **Format.** One lesson per line: ``- **L-NNN** · `tag` `tag` · `enforcement` — text``. The ID is stable: never renumber or reuse one. *Module tags* (`server`, `web`, `kmp`, `android`, `ios`, `sdk`) limit a lesson to projects that have such a module; every other tag (`workflow`, `git`, `qa`, `hosting`, `push`, ...) applies to all projects. *Enforcement* says how the lesson is kept: `rule` (a rule in `.claude/rules.md`, usually followed by a hook), `policy-check` (a script or the gate), `template` (built into the generated files) or `note` (advice only).
>
> **Growing.** A finished task records `- Lesson: <one line or none>`; `tasks.py set <ID> DONE` copies a real one to the project's `docs/knowledge/LESSONS.local.md`; `SYSTEM_SETUP lessons import <project>` reviews those, removes duplicates and business names, and adds what the person approves here with a new ID. `SYSTEM_SETUP lessons list [--tag X]` shows them.

## 1. Workflow & tokens
- **L-001** · `workflow` · `template` — Auto-loaded files (root `CLAUDE.md`, rules, roles, hooks, session, memory, the project's `CLAUDE.md`) are never read with a tool — they are already in context; re-reading them is pure token waste and was the largest avoidable cost.
- **L-002** · `workflow` · `rule` — Backlogs are read only through the tool (`tasks.py next|show|set|board|blocked|check`); a 400-row table read whole costs more than the task it introduces.
- **L-003** · `workflow` · `rule` — Requirements are read by heading (`grep -n "^### S07"` then `sed -n`), never a PRD/BRD whole; the task row names the sections and operation ids to read.
- **L-004** · `workflow` · `rule` — One project per session: only that folder's `CLAUDE.md`/session/memory load; cross-project facts live in `INTEGRATION.md` §1–§6 and root memory.
- **L-005** · `workflow` · `rule` — Write acceptance criteria first, in the project's session block, naming PRD §/BUSINESS_DOMAIN §/operation ids — reviews and tests are checked against that list, not against memory of the conversation.
- **L-006** · `workflow` · `note` — Order verification cheap → expensive: static checks and host unit tests first, the full multi-variant gate once per batch, device/browser runs once per backlog; the 15–40 minute gate is then rarely wasted.
- **L-007** · `workflow` · `rule` — Batched verification (write five tasks, verify once) saved hours; each block stays `Loops: 0/1` / `Review: PENDING` until the batch run actually happened.
- **L-008** · `workflow` · `rule` — Never record a loop or review as passed when it did not run, even when a hook nags; honest session records are the only way the next session knows what is verified.
- **L-009** · `workflow` · `rule` — Report coverage gaps as their own list ("not checked: RTL, dark, iOS, landscape") — "gate passed" is not "seen on a device".
- **L-010** · `workflow` · `note` — Run every gate quietly and read only its summary/tail; open the full log only on failure. Never grep-filter a gate's output as the pass signal: a filtered pipe once hid a failing step (exit 2, no lines).
- **L-011** · `workflow` · `note` — Chain build + install + device steps into one terminal command when possible: one wait and one result instead of many polling round trips.
- **L-012** · `workflow` · `note` — Treat an agent's "passed" as a claim until the orchestrator re-runs it or reads the diff; agents reported green runs that never compiled (sandbox without Gradle) or that were skipped.
- **L-013** · `workflow` · `note` — Read the risky parts of a diff yourself before merging: shrinker/keep rules, manifests, build settings, lockfiles — they compile cleanly and break at runtime (one R8 change hid a release tab bar).
- **L-014** · `workflow` · `note` — When a script you wrote fails, suspect the script first (wrong task name, zsh word splitting, BSD vs GNU `sed`, prettier re-wrapping your edit anchors); several "failures" were tooling, one committed conflict markers.
- **L-015** · `workflow` · `policy-check` — Keep session files to current + last two blocks and memory to one line per finished task; both load every turn, and stale memory lines contradicted later behaviour.
- **L-016** · `workflow` · `policy-check` — Files ≤ 300 lines (code, tests, locales) — small files are cheaper to read and review in every later session; enforce the limit in the gate.
- **L-017** · `workflow` · `rule` — Brief subagents tightly (goal, files, what is ruled out, scope, report length) and run one per feature sequentially; six parallel agents burned ~1.6M tokens and hit the usage limit mid-run with work uncommitted.
- **L-163** · `workflow` `push` · `note` — Never swallow a registration error silently (an empty catch around token or push registration): log it and surface it, or a whole delivery path stays dead and unseen.
- **L-164** · `workflow` `hosting` · `note` — Before creating anything outside the repository (a cloud project, a bucket, a service, a remote branch, a shared folder), search for what already exists: a duplicate splits traffic and credentials between two copies.
- **L-165** · `workflow` `kmp` · `note` — A generator that derives new apps from a live app must mirror every new dependency of the live app in its slim shell (or its removal list); its own test runs one full generation so the drift shows at once.

## 2. Git, branches and masters ↔ main sync
- **L-018** · `workflow` `git` · `rule` — Branch per task from the freshly fetched project master, created with `git branch --no-track <name> origin/<master>` (the sandbox cannot write `.git/config`, so `-u`/tracking fails halfway); check `git branch --show-current` before the first edit.
- **L-019** · `workflow` `git` · `note` — PRs target the project master, never `main`; the owner merges masters into `main`. If a master is behind `main`, merge `main` into it by PR first — otherwise the master → `main` PR cannot merge.
- **L-020** · `workflow` `git` · `note` — Conflicts between masters and `main` happen almost only in shared bookkeeping: the generated board, backlog rows, root session index. Keep both sides, then regenerate the board from the backlogs (`tasks.py board`); never hand-merge a generated section.
- **L-021** · `workflow` `git` · `note` — Resolve on a dedicated sync branch (`chore/sync-main-into-<master>-N`), locally, before opening PRs: conflicts show early, hosted merges take minutes each, and the masters stay clean.
- **L-022** · `workflow` `git` · `note` — When several masters conflict repeatedly, merge them into one integration branch off `main` and resolve once instead of re-resolving the same churn per master.
- **L-023** · `workflow` `git` · `note` — After a conflict resolution, grep for `<<<<<<<` and for missing backlog rows before committing; a batch resolution once committed markers silently.
- **L-024** · `workflow` `git` · `note` — Before starting a task whose backlog rows sit next to a just-merged task's rows, merge the updated master into your worktree first — neighbouring rows in the same table conflict for sure.
- **L-025** · `workflow` `git` · `note` — Keep each PR to its own project's files; a branch that picked up an unrelated commit is rebuilt clean, not merged — cross-project commits leak into the wrong master and deploy.
- **L-026** · `workflow` `git` · `note` — A merge that needs new env vars must wait until the hosting environment has them; merge into the masters meanwhile — an auto-deploying branch broke the running service, sometimes with the old version silently serving.
- **L-027** · `workflow` `git` · `note` — After a status-changing merge, propagate: rows DONE, rows stuck at IN REVIEW fixed, new rows for discovered gaps, board regenerated — stale backlogs made blocked work look ready and ready work look blocked.
- **L-028** · `workflow` `git` · `rule` — `tasks.py set <ID> DONE` is the only way to unblock dependents in other projects (BLOCKED → TODO) and rewrite the board; commit those file changes with the task.
- **L-029** · `workflow` `git` · `note` — A gitignore pattern `reports/` also matched `src/**/reports/` and two feature folders were never committed: anchor patterns (`/reports/`) and run `git status --ignored` after adding a feature.
- **L-030** · `workflow` `git` · `rule` — Never commit secrets: ignore credential files by pattern, never use `user:pass@host` URLs or secret-shaped literals in tests (`'a'.repeat(48)` instead) — scanners flag even placeholders and a flagged commit stays in PR history.

## 3. Parallel agents & environment
- **L-031** · `workflow` · `rule` — One worktree per agent (`.claude/worktrees/<agent>`, git-ignored) and one agent per master; hooks resolve the checkout from the command's `cwd`, so each worktree is judged on its own branch.
- **L-032** · `workflow` · `rule` — One heavy gate at a time per machine: concurrent Gradle/Xcode/npm builds collide on the shared daemon and caches (`Timeout waiting to lock …`, out-of-memory, 95 % disk). About one build-heavy agent per app is the practical limit.
- **L-033** · `workflow` · `rule` — Never stop or kill shared daemons (Gradle, emulators, a local server another agent tests against); finish or hand over. Do stop leftover command-line daemons before an IDE sync — several daemons competing for memory failed syncs even after raising the heap.
- **L-034** · `workflow` · `rule` — Commit small and often, and always before a long build: sessions are dropped by `ECONNRESET`/DNS errors and usage limits, agents stall after ~10 minutes without progress; committed work in the worktree survives, uncommitted work is rescued by hand.
- **L-035** · `workflow` · `rule` — Poll long builds with short reads (background command or terminal tab + `tail`), never block one turn on a 30-minute build — blocking waits looked like stalls and timed out the agent.
- **L-036** · `workflow` · `rule` — A dropped agent is resumed in its own worktree on its own branch; if it cannot be resumed, a fresh agent continues there with the commits and uncommitted files intact.
- **L-037** · `workflow` · `rule` — Watch disk before each heavy round: remove merged worktrees (unlink shared dependency symlinks first), delete only your own DerivedData/Kotlin outputs; a full disk produced "no space" gate failures and truncated binaries that looked like link errors.
- **L-038** · `workflow` · `rule` — Terminal panel tabs are limited (~6) and echo their whole screen when read or closed: one tab per long process, close after use, keep output short.
- **L-039** · `workflow` · `rule` — The sandbox cannot bind local ports (EPERM on listen), run `gh`, write `.claude/hooks/`, `.claude/settings*.json` or `.git/config`: send those steps through the Terminal panel, say so in the report, and classify EPERM-on-listen test failures as sandbox noise before judging the code.
- **L-040** · `workflow` · `rule` — Pushes/merges made through the terminal bypass the Bash guard hook, so the `Loops: 1/1` + `Review: PASSED` lines must be true and written before them; the guard reads `session.md` before the command runs — write the block in one call, push in the next.
- **L-041** · `workflow` · `rule` — After inspecting another agent's worktree, move your shell back to the main checkout on a master; the Stop hook judges the current branch and misfires on someone else's unfinished task branch.
- **L-042** · `workflow` · `note` — Never run two e2e suites, or e2e and a preview server, on the same port; a preview started from a shared config may serve the main checkout rather than your worktree — serve the worktree yourself on its own port.
- **L-043** · `workflow` · `note` — Builds run from a real terminal, not the sandboxed agent shell: it could not write `~/.gradle` and blocked the SDK/Maven hosts, so "done" was once claimed without a compile. Decide early where builds run.
- **L-044** · `workflow` · `note` — Maven Central 429 rate limits in CI/runners: point the build at a mirror.
- **L-045** · `workflow` · `note` — The system `python3` may be old (3.9): policy/tool scripts use `from __future__ import annotations` for `X | None`, or they work on dev machines and fail elsewhere.

## 4. Server (Node/Express/Mongoose/Redis/Socket.IO/BullMQ)
- **L-046** · `server` · `note` — Generate the OpenAPI from the same validation schemas, mount every router through one helper, and fail a test on stale generated files, routes without docs or docs without routes — otherwise clients integrate against a drifted contract.
- **L-047** · `server` · `note` — Keep a per-namespace contract fingerprint + version with a client-impact note; a test fails on any change not recorded, so breaking changes cannot reach clients unannounced.
- **L-048** · `server` · `note` — Generated spec gotchas that bit clients: optional objects omitted instead of empty, id patterns no real id matches, idempotency headers missing from one namespace — check the spec against a real response before a client ships.
- **L-049** · `server` · `note` — Status changes are an atomic compare-and-set in the repository (`transition(id, fromStatuses, set)`), used by every path that can settle the same record (client verify and webhook) — the main defence against double-settle/double-refund races.
- **L-050** · `server` · `note` — Take Redis locks over every contended key (multi-key), pass the domain "busy" error into the lock helper and re-validate the rule inside the lock; checks made before the lock are stale.
- **L-051** · `server` · `note` — Side effects (sockets, notifications, refunds, ledger, jobs) go through injected hook ports defaulting to no-op and never throwing — services stay testable and a failing side effect cannot roll back the main write.
- **L-052** · `server` · `note` — Job queue behind a scheduler port, deterministic job ids from domain parts (`kind.entityId.offset`), plus a startup `reconcile()` — rescheduling is idempotent and jobs lost in downtime are rebuilt.
- **L-053** · `server` · `note` — Bind the socket hub late through a relay the services hold; services exist before the socket server and late binding avoids the circular dependency.
- **L-054** · `server` · `note` — Money as integer minor units; round a percentage once on the total and derive the other part by subtraction — two separately rounded parts drift and no longer sum.
- **L-055** · `server` · `note` — Pass the time zone explicitly to every date helper, use half-open ranges, define DST gap/overlap behaviour — closed ranges made back-to-back slots conflict.
- **L-056** · `server` · `note` — Rate limiter as one Lua script; sensitive limiters (OTP, login, payments) fail closed, only the global one fails open — a Redis outage must not mean unlimited login attempts.
- **L-057** · `server` · `note` — Normalize every Redis outage signature (connection closed, command timed out, max retries, offline queue) to one 503 error type, or each surfaces as a differently shaped 500.
- **L-058** · `server` · `note` — Express 5: start with `http.createServer(app).listen` — `app.listen` reports a port-in-use through its callback and startup failures pass unnoticed.
- **L-059** · `server` · `note` — Mongoose: conditionally-required fields use `required: function(this){…}` (custom validators do not run on `undefined`); with `autoIndex: false` in production, create indexes at startup from a central model list and test that every model is in it.
- **L-060** · `server` · `note` — ioredis: `quit()` not `disconnect()` on possibly-closed clients (a 2 s timer keeps Jest hanging); `duplicate()` for subscribers and BullMQ workers with `maxRetriesPerRequest: null` and no command timeout — blocking commands break under API-client settings.
- **L-061** · `server` · `note` — Keep `req.rawBody` only under the webhook prefix (signatures need raw bytes; everywhere else wastes memory); retry unique-reference generation only on a duplicate-key error for that field.
- **L-062** · `server` · `note` — Settings cached in Redis with a version compare-and-set and a default fallback (with warning) on invalid stored values — stale writers cannot overwrite newer values and one bad row cannot crash the app.
- **L-063** · `server` · `note` — Readiness probes never depend on third-party providers — a vendor outage must not take every instance out of rotation.
- **L-166** · `server` · `note` — Delete stored files through an outbox (record the key, delete after the owning write commits, retry): a failed storage call must neither roll back the business write nor leave orphans.
- **L-167** · `server` `workflow` · `note` — Keep a feature the business paused in the code behind a provider value `disabled` in production, so the flow still works (for example pay on arrival) and switching it back on is configuration, not a rewrite.

## 5. Admin web (React + TypeScript + Vite)
- **L-064** · `web` · `note` — Every external dependency behind a domain interface with remote and mock implementations chosen by one env switch (`VITE_DATA_SOURCE`), the mock compiled out of prod by a build-time define and a bundle check that fails if dev-only names appear in a prod chunk.
- **L-065** · `web` · `note` — The mock is a fake `fetch` transport under the real HTTP client, not a mock repository — page tests then cover envelope validation, refresh and error mapping; give it per-route closure state, a scenario switcher (`serverError`, empty, slow), server-shaped 409/422 errors and dates relative to now (fixed dates go stale).
- **L-066** · `web` · `note` — A test that every contract operation has a mock fixture (with an explicit exempt list) — otherwise new operations fail silently in dev.
- **L-067** · `web` · `note` — Contract sync (`api:sync`): committed OpenAPI copy, DTOs as lazy schema factories + types, an `OPERATIONS` map with stable ids from method + path; generated code excluded from lint/format/coverage/size/hardcode checks. Hand-written DTOs drift; hand-overridden generated patterns (id regexes) hid contract bugs — fix the server contract and add a test that fails on overrides.
- **L-068** · `web` · `note` — Generate a doc of consumed operations checked by the gate (with an exemptions file) and tests that compare enum-driven UI (status badges, error-code catalog) with the contract's enums and codes — new server values otherwise render as raw strings.
- **L-069** · `web` · `note` — Branch on error `code`, never on message text; show the server's localized message when present.
- **L-070** · `web` · `note` — Every list paginated on the server; list state in the URL (`page`, `pageSize`, `q`, `sort=key:dir`, one param per filter) through pure parse/serialize functions and a multi-filter setter — deep links, back button, no double fetch.
- **L-071** · `web` · `note` — Sessions: tokens in memory mirrored to `sessionStorage` (schema-validated at start, never `localStorage`); one single-flight refresh on 401 then sign-out with a shown reason — parallel 401s otherwise start several refreshes and sign the user out.
- **L-072** · `web` · `note` — Wrap lazy routes in a loader that reloads once on a failed chunk (with a timestamp guard) — after a deploy, open tabs request chunk files that no longer exist.
- **L-073** · `web` · `note` — RTL default with logical CSS only (`inline-start/end`), `minmax(0, 1fr)` grids and `position: relative` on scroll boxes — tables and visually hidden/absolutely positioned children made the page scroll sideways; one viewport hook sets `data-bp`/`data-orientation` on `<html>` so components and e2e read one breakpoint.
- **L-074** · `web` · `note` — Locale files split per area under 300 lines, large areas lazy, tests for key parity/empty values/placeholder mismatches; no dots or plural suffixes in keys.
- **L-075** · `web` · `note` — Bundle budgets (entry, per-chunk, CSS, total JS in prod) — the shell sat at 99.8 % of its entry budget, so small imports broke the build; measure before adding to the shell.
- **L-076** · `web` · `note` — Vite: files imported by `vite.config.ts` use relative imports with `.ts` extensions, `vite preview` needs `--mode <variant>`, CSP `font-src` needs `data:` (inlined small fonts); commit only placeholder `.env.dev`/`.env.prod` with a schema that names missing keys only.
- **L-077** · `web` · `note` — Unit tests cannot see CSS layout: measure widths/positions in a real browser (a drawer rendered 185 px wide with every test green) and return one compact JSON of measurements instead of screenshots.
- **L-078** · `web` · `note` — When the browser pane is hidden, clicks and `.focus()` do not fire React handlers — use `form.requestSubmit()` and dispatched `focusin`/`mouseover`.
- **L-079** · `web` · `note` — Run axe in both languages and lock WCAG AA contrast in a token test (4.5:1 on every surface) — theme regressions get caught without a manual pass.

## 6. KMP Android
- **L-080** · `kmp` `android` · `note` — Four variants (dev/prod × debug/release) compile on every PR; release stays R8-minified with explicit keep rules and a test per reflective lookup — release-only breakage otherwise shows up in prod.
- **L-081** · `kmp` `android` · `note` — Lint and Kotlin treat warnings as errors: deprecated Compose APIs fail the build; do not build with `-q` when checking warnings (quiet hides `w:` lines) — grep `^w:` from a full log.
- **L-082** · `kmp` `android` · `note` — KMP library modules have no `compileDebugKotlinAndroid`; use `:app:assemble<Flavor><Type>` or `:<module>:testAndroidHostTest`.
- **L-083** · `kmp` `android` · `note` — Dev gets its own application-id suffix; Firebase config is tied to the id, and every `pm clear`/launch targets the right package.
- **L-084** · `kmp` `android` · `note` — Apply the crash-reporter Gradle plugin in the app convention plugin — missing it aborted the app at startup and skipped mapping uploads.
- **L-085** · `kmp` `android` · `note` — Detekt rules that bite in bulk: line length 140, complexity ≤ 15 (mappings as tables, reducers split into `handleX(event): Boolean` chained with `||`), `rememberUpdatedState` for lambdas in `LaunchedEffect`, composable parameter order, `modifier = Modifier` on private composables, present-tense lambda names, new CompositionLocals added to `allowedCompositionLocals`, `ignored` as the swallowed-exception name.
- **L-086** · `kmp` `android` · `note` — `/*` inside KDoc or strings (`core/*`, `"image/*"`) opens a nested comment — compile error or policy-lexer hit; build such values from constants.
- **L-087** · `kmp` `android` · `note` — Baselines (detekt, policy) are ratchets that only shrink, or stay empty from day one on a new app — the second app proved an empty baseline is achievable.
- **L-088** · `kmp` `android` · `note` — Pin transitive KMP libraries to the version the HTTP client pulls (e.g. kotlinx-datetime); a lower catalog version mixes klibs and causes `IrLinkageError` on iOS only.
- **L-089** · `kmp` `android` · `note` — MVI-delegate ViewModels: `onStart` re-runs on every re-subscription, so guard one-shot loads; read the delegate's `uiState.value`, not the lagging `stateIn` value; tests keep one collector in `backgroundScope` with `UnconfinedTestDispatcher`.
- **L-090** · `kmp` `android` · `note` — Koin `viewModelOf` cannot resolve constructor lambdas or defaults of non-Koin types — use `viewModel { X(get(), …) }`; a feature `di` module referencing core types declares those dependencies itself.
- **L-091** · `kmp` `android` · `note` — Generated DTOs/operations from OpenAPI (`apiSync --check` in the gate, generated code excluded from detekt/policies) and fixtures from the same spec plus captured real responses; fixtures need value hints (unique ids per list item — lazy lists keyed by id crash on duplicates; `allOf` responses generate as `data: null` and are hand-written).
- **L-092** · `kmp` `android` · `note` — Policy scripts cover what detekt cannot: hardcoded user-visible strings, `https://` literals, secret-named constants, every screen tracking itself, every navigated route registered. Compose string resources print `\'` and `%%` literally; counted text uses `<plurals>` per language.
- **L-093** · `kmp` `android` · `note` — Emulator QA: pass `-s <serial>`/`ANDROID_SERIAL` with several emulators; journey = `pm clear`, launch, `screencap`, `dumpsys activity activities | grep topResumedActivity`, logcat `FATAL EXCEPTION|Caused by`; rotation via `accelerometer_rotation 0` + `user_rotation 1`; `geo fix` does not feed the fused provider (`cmd location … add-test-provider`); keyboard closes with keyevent 4; low-RAM AVDs ANR under load and the emulator clock drifts.
- **L-094** · `kmp` `android` · `note` — Local stack from the emulator: host `10.0.2.2`, an untracked debug manifest allowing cleartext (never committed), `adb reverse` for object storage — do not weaken the shipped network security config.
- **L-157** · `android` `push` · `note` — firebase-messaging 26: `register()` throws `API disabled` unless the manifest sets the flag `firebase_messaging_installation_id_enabled=true`. Add it when moving to 26 and prove token registration on a real device.
- **L-158** · `android` `kmp` `push` · `note` — When a push-token sync reads the token inside the sync (and syncing can trigger a token refresh), remember the last token sent and skip an identical one; without that it loops (one real case reached 152 requests in 90 s).
- **L-159** · `android` `push` `qa` · `note` — A force-stopped Android app receives no FCM until it is opened again: launch it once after `force-stop` or a fresh `adb install` before judging delivery.
- **L-160** · `android` `ios` `kmp` `qa` · `note` — A device build from another checkout (same application id) silently replaces your test build: check which checkout built the installed app before trusting a result.

## 7. KMP iOS
- **L-095** · `kmp` `ios` · `note` — xcconfig: `//` starts a comment, so URLs are written `https:/$()/host` or the value is silently cut to `https:`; an empty-value regex in a generator once ate the next line (the prod bundle id) — test generators on real xcconfig text.
- **L-096** · `kmp` `ios` · `note` — Four configurations (Debug/Release × Dev/Prod), one shared scheme per environment, xcconfig → Info.plist → one `AppEnvironment`; a git-ignored `Local.xcconfig` overrides for local-stack runs (ATS-allowed IP there).
- **L-097** · `kmp` `ios` · `note` — Placeholder Firebase plist keys crash iOS at launch in Installations key validation (and throw on Android) — catch it in providers; get real dev files before simulator QA.
- **L-098** · `kmp` `ios` · `note` — Sign simulator builds ad hoc (`CODE_SIGN_IDENTITY=-`); `CODE_SIGNING_ALLOWED=NO` breaks the Keychain, so secure storage fails and the app looks signed out — a build flag that looks like an auth bug.
- **L-099** · `kmp` `ios` · `note` — K/N: never call a suspend function inside the argument list of an ObjC call (earlier arguments are converted and raw pointers kept across the suspension → SIGSEGV in `objc_retain`); load values first, then build ObjC objects in a non-suspend function.
- **L-100** · `kmp` `ios` · `note` — K/N with `-Werror`: `String as NSString` rejected, `NSData.create` needs `@OptIn(BetaInteropApi::class)`, `CFBridgingRetain` is in `platform.Foundation`, MapKit delegate overloads need `@ObjCSignatureOverride`.
- **L-101** · `kmp` `ios` · `note` — Kotlin types Swift implements (bridges) must come from a module exported from the shared framework (`export(project(...))` + `api`), or Swift cannot see the interface.
- **L-102** · `kmp` `ios` · `note` — Adding an SPM product without Xcode needs four pbxproj entries (PBXBuildFile, Frameworks phase, packageProductDependencies, XCSwiftPackageProductDependency); a partial patch builds locally and fails to link.
- **L-103** · `kmp` `ios` · `note` — The iOS gate (4 configurations + simulator K/N tests) takes ~10 minutes and much disk: delete DerivedData/Kotlin outputs between configurations on a full disk and keep a skip flag for Android-only runs.
- **L-104** · `kmp` `ios` · `note` — A cold-start timeout against a sleeping remote dev API must show an error + Retry, not a crash; a Swift-facing name (`MainViewController`) may need a detekt exception.

## 8. SDKs / packages (ports + adapters)
- **L-105** · `sdk` · `note` — Lazy-load heavy vendor SDKs and use `require()` in the CJS build rather than native `import()` — native dynamic import fails under Jest/ts-node in consumers, found only when wiring the SDK into the server.
- **L-106** · `sdk` · `note` — Gate each release with a pack → install into a temp project → call through `require` and `import` smoke test; unit tests cannot catch a broken `exports` map or dual build.
- **L-107** · `sdk` · `note` — Map every vendor status explicitly; unknown values go to `UNKNOWN` (logged raw, never success); typed errors carry `code`, `retryable`, `cause` and secret-free `details` — treating unknown as success is how a payment gets marked paid.
- **L-108** · `sdk` · `note` — Idempotency: same key + same request → first result; same key + different request → conflict; failed send forgotten so the caller retries; short TTLs because a crashed in-flight record blocks the key.
- **L-109** · `sdk` · `note` — Retry only safe calls, reuse one vendor idempotency key across retries, never retry a non-idempotent POST (refund) — look up by merchant reference first; never retry a malformed 2xx; cap retry-after hints.
- **L-110** · `sdk` · `note` — A redacting logger that hides keys containing `code`/`token`/`key` also hides error codes — log them under a neutral field.
- **L-111** · `sdk` · `note` — Prod mode strict at construction: refuse fakes, dry-run, http endpoints, in-memory stores; require secrets; check the credential's project id matches the configured one; name only the bad option keys in errors.
- **L-112** · `sdk` · `note` — A loop test per SDK (hundreds of flows, ~20 concurrent, duplicate keys, injected transient failures) asserting exactly-once effects, no leftover keys/objects, flat heap — unit tests do not show leaks or idempotency races.
- **L-113** · `sdk` · `note` — Enforce what the vendor cannot (presigned PUT cannot cap size) at a confirm step: magic bytes + size, delete on failure; never trust client-declared type or size.
- **L-114** · `sdk` · `note` — The server keeps its own port and a thin adapter mapping SDK errors (outage → 502/503, caller bug → `RangeError`), so swapping or dropping an SDK never touches domain code; a paused feature keeps the port with a `disabled` provider production selects explicitly.
- **L-115** · `sdk` · `note` — Watch ranges that differ between vendor and consumer settings (vendor accepts 4–6 digit codes, admin setting allows 10) — a legal setting then causes a 503 on every request.
- **L-116** · `sdk` · `note` — Sibling `file:` SDK dependencies force the Docker build context to the repo root and an `ensure-sdks` script that builds them first.

## 9. QA & e2e
- **L-117** · `qa` · `note` — A local full stack (database, cache, object storage, server with fake providers) when the shared remote is stale or broken — the code under test is identical and QA stops waiting.
- **L-118** · `qa` · `note` — Before blaming the client, check the remote directly: health vs a new endpoint (404 = old deploy), seed counts, free-tier cold start and blocked outbound ports — several "app bugs" were an old server or missing data.
- **L-119** · `qa` · `note` — Device/browser journeys once at the end of a backlog across every locale/direction, theme, orientation and font scale — one pass catches cross-cutting defects cheaply; per-task device runs are slow.
- **L-120** · `qa` · `note` — Crashes, contract gaps and server defects found during client journeys become new server tasks with tests, tracked separately from client fixes — client QA was the main source of server bug reports.
- **L-121** · `qa` · `note` — Rule out tooling artifacts before filing bugs: clock skew, adb dropping characters, low memory, a stale install, an emulator that will not rotate, a stale build older than your edits.
- **L-122** · `qa` · `note` — Measure layout bugs with numbers (widths, negative RTL offsets, width sweeps) and tighten weak e2e assertions until they fail on the known bug — an e2e that passes with the bug present proves nothing.
- **L-123** · `qa` · `note` — Server tests: a fake model whose operator support grows (record its gaps), one Redis logical DB per worker with `flushdb` never `flushall`, repeated socket emits (the adapter subscribes asynchronously), concurrency tests against the service not HTTP (route limiters throttle the test), tokens re-signed under the real clock, single-use proofs never reused across calls.
- **L-124** · `qa` · `note` — Web e2e: one Playwright run at a time (port sharing), selectors scoped to a labelled container with `exact: true`, `selectText()` instead of Ctrl+A on macOS, client-side navigation with one token in real-server sweeps (reloads hit per-IP limits); `waitFor` hangs under fake timers — `act(() => vi.advanceTimersByTimeAsync(n))`.
- **L-125** · `qa` · `note` — Property tests with a seeded PRNG + independent oracle; security checklists as tests (every admin route rejects a missing admin token).
- **L-126** · `qa` · `note` — On red CI replay in a clean clone with `npm ci` first; jobs dying in seconds with no steps are a platform/billing problem. Mutation loops run in a separate worktree — interrupted runs leave untracked mutations.
- **L-127** · `qa` · `note` — A structured diagnostic log around external flows (sent, timing, error codes) separates app bugs from provider/carrier delivery problems in one read.
- **L-161** · `qa` `push` `hosting` · `note` — Prove push fixes on a hosted environment with a real device push: a local fake notifier hides delivery bugs (credentials, project mismatch, registration).
- **L-162** · `qa` `push` · `note` — Report token, delivery and display as three separate facts (the token reached the server; the provider accepted the message; the notification was shown): one green says nothing about the next.

## 10. Hosting, env and secrets
- **L-128** · `hosting` · `note` — Env validated by a fail-fast schema; a test that every schema key appears in `.env.example`; an `env:check <file>` that validates key names only — config should fail at deploy, not on the first request.
- **L-129** · `hosting` · `note` — A hosted dev environment that runs `NODE_ENV=production` gets full prod strictness: tell environments apart by credentials (separate vendor projects, buckets, keys) and warn at startup when test-mode keys run in production mode.
- **L-130** · `hosting` · `note` — Some hosts block outbound SMTP: keep an HTTP-API email adapter behind the same channel port; provider "From" must equal the authenticated account and daily caps apply.
- **L-131** · `hosting` · `note` — Behind an HTTP proxy, some vendor SDKs ignore `HTTPS_PROXY` and HTTP/2 transports cannot be proxied — expose injectable agent/legacy-transport options.
- **L-132** · `hosting` · `note` — From the host, a replica-set database container needs `directConnection=true`, or the driver chases internal hostnames.
- **L-133** · `hosting` · `note` — Config values the owner must set are requested by key name only; secrets never travel through chat and env values are never printed — tell owners to paste into the host and rotate anything exposed.
- **L-134** · `hosting` · `note` — A change that needs new env keys ships to masters first and to the deployed branch only after the owner confirms the keys; the deployed branch is the only place a merge is a deploy.
- **L-135** · `hosting` · `note` — Firebase (or equivalent) client files with live keys live outside git; committed placeholders must build with the SDK off; real dev files are an owner input listed as a PENDING row.
- **L-168** · `workflow` `hosting` · `rule` — Never `source` or print an env file: a multi-line value (a private key) was echoed into a terminal once. Read key names only, never values.

## 11. Owner decisions (how to handle them)
- **L-136** · `workflow` · `note` — Record decisions as dated one-liners in a "replace, don't append" memory and update the domain source of truth in the same PR — later sessions neither re-ask nor contradict.
- **L-137** · `workflow` · `note` — Everything only the owner can supply goes into one short numbered list at the end of each report with exact steps; the rows stay PENDING/BLOCKED with the blocker named — owners act on a checklist, scattered asks get lost.
- **L-138** · `workflow` · `note` — Skip owner-blocked tasks instead of stopping the backlog; keep an explicit "open questions / unverified against the real vendor" list with the safest default behind configuration.
- **L-139** · `workflow` · `note` — Build blocked work up to the external boundary with fakes or test triggers in place, record it as a deviation — the feature ships and is tested; only the delivery step waits for credentials.
- **L-140** · `workflow` · `note` — When a blocker is satisfied another way (an equivalent environment exists), add a DONE row for that and repoint dependents; leave the original owner task open so the record stays true.
- **L-141** · `workflow` · `note` — When a newer owner instruction contradicts an older backlog row, follow the newer one and ask for confirmation; when documents conflict, stop and ask instead of guessing; mark superseded documents `LEGACY — do not implement`.
- **L-142** · `workflow` · `note` — Make small reversible technical choices yourself and record them; escalate only costly-to-reverse, money/vendor or security trade-offs — waiting on every choice stalls the backlog.
- **L-143** · `workflow` · `note` — A fix that needs a protected path the agent cannot write (hooks, settings) is offered as an exact patch or run outside the sandbox with approval — rules and hooks stay owner-controlled.
- **L-144** · `workflow` · `note` — Process permissions are written as explicit conditional rules ("may self-merge only after the full local gate is green") and updated when the owner changes them.
- **L-145** · `workflow` · `note` — Verification cadence decisions (one loop; batched every five; local gates, no CI; e2e only on request) are recorded with their date in rules and memory so hooks and agents enforce the same thing.
- **L-169** · `workflow` · `note` — When the business changes, rewrite the requirement documents from the new business and mark design files that predate it as visual reference only; agents otherwise build screens for features the business dropped.

## 12. Token cost and the feature line (measured on a real feature)
- **L-146** · `workflow` · `note` — **Cost = requests × context.** Each response resends everything, so later steps cost the most. Long main sessions averaged ~450k tokens per request; sub-agents started at ~68k and read ~33M from cache each.
- **L-147** · `workflow` · `note` — **Thin workers are real.** Start size with only the needed tools, no MCP, no skills, no project memory: 6.8k tokens, 3k for a read-only reviewer; 10.5–12.4k with the task card. Keep the measured numbers next to the targets, and report a missed target as missed.
- **L-148** · `workflow` · `note` — **First real feature (two modules, one contract change):** 198 requests, 7.7M tokens through the model, $2.28 plus two stopped workers that never reported a cost. Uninterrupted workers read 2.1M and 3.0M from cache against a 1M target: missed. Context grew from 11k to 100k in one worker.
- **L-149** · `workflow` · `note` — **A fresh context beats a long one.** The worker stopped at 100k context was finished by a new one for 215k cache read and $0.19, told only what was already on its branch. Short lives matter more than a small start.
- **L-150** · `workflow` · `note` — **A custom system prompt drops the default advice to batch tool calls**, and each lone read or edit becomes a request. Say it again in the worker prompt.
- **L-151** · `workflow` · `note` — **Naming the known files in the packet is the cheapest saving:** exploration is what grows the context.
- **L-152** · `workflow` · `note` — **Set caps from measurements.** A first guess (800k) stopped a healthy worker; a stopped worker keeps its work and the retry continues it. A stopped agent reports no cost: show unknown, never zero.
- **L-153** · `workflow` · `note` — **Scripts do what scripts can.** Formatting failures reached a model until a format step ran before QA. A reviewer on green code only is cheaper and more useful.
- **L-154** · `workflow` · `note` — **A worktree comes from the master.** A script added on the tool's own branch is not there, and a fresh worktree has no built local packages: setup must build them, or the worker spends tokens working out why the compiler fails.
- **L-155** · `workflow` · `note` — **Hooks in a thin worker:** `--settings` hooks still run with `--setting-sources ""`, so the enforcing hooks stay on at no context cost. A PreToolUse hook fires before the permission check; test the deny list separately. Allow and deny lists are guardrails, not a sandbox.
- **L-156** · `workflow` · `note` — **Read the diff yourself before merging.** The reviewer's PASS is one opinion; running the real commands found a crash in the usage report that every unit test had missed.
